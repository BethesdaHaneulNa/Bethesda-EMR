# 변경 기록(로그) — 누가 무엇을 고쳤는지

> 실장님 결정 2026-09-29 (`decisions.md`): **공통 로그를 만들고 여섯 가지를 남긴다.**
> 일하는 화면에는 「수정됨」 같은 표시를 붙이지 않는다. 기록은 뒤에서만 남고, 관리자만 읽는다.
> 뼈대(표 + 기록 함수)는 총괄이 만들었고, 각 모듈 세션이 자기 화면의 기록을 붙인다.

## 1. 무엇을 남기나

| 남기는 것 | action (코드) | 붙이는 세션 |
|---|---|---|
| 검사 결과를 고침 (처음 입력은 아님) | `laboratory.result.edit` | 임상병리 |
| 끝난 진료 기록을 고침 | `consultation.record.edit` | 진료 |
| 처방을 지움 | `consultation.prescription.delete` | 진료 |
| 오더를 지움 / 취소함 | `consultation.order.delete` · `consultation.order.cancel` | 진료 |
| 영수를 취소함 / 정정함 | `payment.receipt.cancel` · `payment.receipt.correct` | 수납 |
| 환자 인적사항을 고침 | `reception.patient.edit` | 접수 |
| 직원 계정을 만듦 / 고침 / 권한을 바꿈 / 비밀번호를 바꿈 | `settings.staff.create` · `.edit` · `.permissions` · `.password` | 설정 |

**남기지 않는 것**

- 조회(누가 무엇을 봤는지) — 만들지 않기로 결정.
- 처음 입력 — 결과를 처음 넣는 것, 새 처방, 새 환자 등록은 평소 일이라 남기지 않는다. **고치거나 지울 때만** 남긴다.
- 재고 — 약국의 재고 기록(`stock_movement`, 약국 → 📦 재고)이 따로 있다.
- 비밀번호 값 — 「바꿨다」는 사실과 누가 바꿨는지만. 값은 어떤 모양으로도 남기지 않는다(함수가 걸러 냄).

## 2. 한 줄에 들어가는 것

언제 · 누가(이름·역할, 그때의 값) · 어느 모듈 · 무엇을(action) · 어느 환자(이름·차트번호, 그때의 값) · 어느 내원 ·
무엇(예: 검사 이름) · **전 값 → 새 값**(바뀐 칸만).

- 이름을 그때의 값으로 복사해 두는 이유: 나중에 직원 이름이 바뀌거나 처방이 지워져도 기록은 그대로 읽혀야 한다.
- **기록은 고치거나 지울 수 없다.** DB가 막는다(`audit_log is append-only`). 관리자도, EMR 자신도 못 한다.
- 백업에 포함된다(DB 전체 백업 안에 들어 있음).

## 3. 어디서 보나

설정 → 「기록」 탭 (설정 권한이 있는 관리자만). — **설정 세션이 만드는 중.**

## 4. 개발자용 — 기록을 붙이는 법

표: `audit_log` (마이그레이션 `022_audit_log.sql`) · 함수: `backend/src/utils/audit.js`

```js
const { writeAudit, ACTIONS } = require('../utils/audit');

// 바꾸는 트랜잭션 안에서, 바꾸기 전 값을 읽어 둔 뒤
await writeAudit(client, req, {
  action: ACTIONS.LAB_RESULT_EDIT,
  patient_id, visit_id,
  entity: 'lab_result', entity_id: row.id,
  summary: 'Hb',                          // 읽는 사람이 찾을 짧은 이름
  before: { value: '12.1', flag: 'L' },
  after:  { value: '13.1', flag: '' },
});
```

규칙

1. **트랜잭션의 `client`를 넘긴다.** 그래야 바꾼 것과 기록이 같이 저장되거나 같이 취소된다. 트랜잭션 없이 바꾸는 곳은 첫 인자를 `null`로.
2. `before` · `after`에는 의미 있는 칸만. 함수가 **값이 다른 칸만** 남기고, 다른 칸이 하나도 없으면 아무것도 쓰지 않는다(`false`를 돌려줌).
3. 지울 때는 `after: null`, 만들 때는 `before: null`.
4. `action`은 `ACTIONS`에 있는 것만. 새 종류가 필요하면 총괄에 요청(실장님 결정 범위를 넘는지 확인해야 함).
5. **기록이 일을 막지 않는다.** 기록을 쓰다 오류가 나도 원래 작업은 그대로 저장되고, 오류는 서버 로그(`[audit] line not written`)에 남는다. 개발자가 없는 현장에서 「검사 결과를 고칠 수 없음」이 「기록 한 줄 빠짐」보다 나쁘기 때문. 함수가 savepoint로 처리하므로 부르는 쪽은 try/catch가 필요 없다.
6. 환자 이름·차트번호는 `patient_id`만 주면 함수가 채운다.
7. 시험은 격리 스택에서: 고침 → 한 줄 생김 / 같은 값으로 저장 → 줄 없음 / 작업이 실패(롤백) → 줄 없음.

- **「끝난 진료」의 기준**(진료 세션): 진료 상태가 완료·서명이거나, 내원 날짜가 오늘이 아님. 오늘 열려 있는 진료를 몇 번씩 저장하는 것은 남기지 않는다.
- 빈 글자 `''`와 NULL은 같은 값으로 본다(화면이 빈 칸을 `''`로 보내기 때문) — 접수·진료 공통.
- 실행 중 EMR에는 2026-09-29에 모두 올라갔고, 그때 기록은 0줄(아직 아무도 고치지 않음).
