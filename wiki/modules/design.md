# 디자인 (Design) — 화면 색 · 주제

> **담당**: 디자인 세션 · 브랜치 `session/design` · 격리 스택 9189 · **마지막 갱신**: 2026-09-30 · **상태**: 1단계(시안) 끝 — **실장님이 고르심: 시안 A · 파랑 그대로 · 기본은 어두운 화면 · 단추는 상단바 · 계정마다 기억** · 2단계 설계 승인됨(총괄, 2026-09-29 밤) · **2단계 (가) 끝**(색 이름표 · 첫 화면 스크립트 · hover — 보이는 변화 없음) · **3단계 진행 중** — 상단바 · 로그인 · 접수 · 임상병리 · 진료 · 수납 · 약국 · 재고 · 공용 창 넷 · 통계 · 설정 끝 — **모든 화면이 끝남** · 2026-09-30 어두운 화면도 같은 기준에 맞춤(7.1) · **주소로 켜는 미리 보기** 들어감(`?theme=light`) · 바꾸는 단추 · 계정마다 기억은 **만들어 시험까지 끝냄 — 따로 둔 가지 `session/design-switch`**(설정 화면이 끝난 뒤 한꺼번에 합침)

## 1. 이 모듈이 하는 일

EMR 화면의 **색**만 맡습니다. 지금 화면은 어두운 색 한 가지뿐이라, **밝은 화면을 만들고 어두운 화면과 바꿔 쓸 수 있게** 합니다(실장님 지시 2026-09-29: 「지금은 디자인이 다크모드 느낌이잖아 그래서 화이트모드도 만들라고」).

- 동작 · 글자 · 배치 · 칸 폭은 바꾸지 않습니다. 색만 바꿉니다.
- 인쇄물(영수증 `Receipt.jsx`, `documents/*`)은 이미 흰 종이 모양이고, 주제와 관계없이 그대로 둡니다.
- 어두운 화면은 v1.4.0 과 한 픽셀도 달라지면 안 된다는 전제로 시작했고, 밝은 화면이 끝날 때까지 그렇게 지켰습니다(3.4). **2026-09-30 에 실장님이 어두운 화면의 흐린 글자 · 단추 · 테두리를 고치기로 정하셨습니다**(7.1) — 그 뒤로는 「정해진 색 말고는 달라지지 않는다」가 전제입니다.

## 2. 화면 사용법 (직원용)

### 2.1 화면을 밝게 · 어둡게 바꾸기

화면 맨 위 줄, 언어 단추(EN · KO · FR) 바로 오른쪽에 두 칸짜리 단추가 있습니다.

| 화면 언어 | 왼쪽 칸 | 오른쪽 칸 |
|---|---|---|
| 프랑스어 | 🌙 Sombre | ☀ Clair |
| 한국어 | 🌙 어둡게 | ☀ 밝게 |
| 영어 | 🌙 Dark | ☀ Light |

1. **☀ Clair(밝게)** 를 누르면 화면이 바로 흰 바탕으로 바뀝니다. 햇빛이 드는 방이나 오래된 모니터에서 더 잘 보입니다.
2. **🌙 Sombre(어둡게)** 를 누르면 원래의 어두운 화면으로 돌아갑니다.
3. 지금 고른 쪽이 파랑으로 칠해져 있습니다.
4. 고른 화면은 **내 계정에 기억됩니다.** 다른 PC 에서 로그인해도 내가 고른 화면으로 나옵니다. 같은 PC 에 다른 사람이 로그인하면 그 사람이 고른 화면으로 바뀝니다.
5. 처음에는 모두 어두운 화면입니다.

### 2.2 바뀌지 않는 것

- 영수증 · 처방전 · 수술기록지 · 의뢰서 같은 **종이와 그 미리보기**는 언제나 흰 종이입니다.
- 진료 화면의 **환자 이름 줄(진한 파랑)** 은 밝은 화면에서도 진한 파랑입니다.
- **영상을 보는 창**은 언제나 검은 바탕입니다.
- 색의 뜻은 두 화면에서 같습니다: 파랑 = 대기 · 고른 것, 노랑 = 진료 중 · 주의, 초록 = 완료 · 받음, 빨강 = 취소 · 미수 · 경고. 색 옆에는 늘 글자나 기호가 같이 있습니다.

### 2.3 로그인 화면

로그인 화면은 아직 누구인지 모르므로 **그 PC 에서 마지막에 쓴 화면**으로 나옵니다. 로그인하면 내 계정의 화면으로 바뀝니다.

### 3.3 주제 장치 (2단계)

> **지금 들어가 있는 것 (2단계 (가), 2026-09-29)**: `frontend/index.html` 의 `<style id="bethesda-theme">`(색 이름표 57개 + 옅은 색 64개 + `--scrim` · `--hover-filter` · `--scheme`), 그 아래 첫 화면 스크립트, `body` 의 바탕 · 글자색과 `button:hover` 가 이름표를 읽음, 새 파일 `frontend/src/theme.js`(`cv()` · `tint()` · `getTheme()` · `setTheme()`). **바꾸는 단추는 아직 없어** 직원은 밝은 화면을 켤 수 없고, 화면 파일은 아직 이름표를 읽지 않습니다. 아래 ①~⑧ 은 설계 전체입니다.
>
> **이름표 표는 `wiki/reference/design/tokens.mjs` 가 원본**입니다. `index.html` 의 블록은 거기서 만들어 붙인 것이므로, 값을 고칠 때는 표를 고치고 `node tokens.mjs` 의 출력으로 블록을 바꿉니다. `node tokens.mjs --check` 는 밝은 값이 기준(글자 4.5, 칸 테두리 3)을 넘는지 검사합니다.
>
> **같은 어두운 색이 역할마다 다른 이름표를 가집니다.** 어두운 화면에서는 같은 색이지만 밝은 화면에서는 달라야 하기 때문입니다: `#0f1117` = `--bg`(화면 바탕) · `--field`(입력 칸 바탕), `#1e2433` = `--chip`(단추 · 꼬리표) · `--line-soft`(표 줄), `#2a3142` = `--border-2`(상자) · `--field-border`(입력 칸), `#fff` = `--on-fill`(색 단추 위 글자 — 두 주제에서 흰색) · `--text-max`(판 위의 흰 글자 — 밝은 화면에서는 검정), `#3b82f6` = `--accent`(채움) · `--accent-ink`(글자). 그래서 3단계에서 색을 이름표로 바꾸는 일은 기계로 한꺼번에 할 수 없고, 쓰인 자리를 보고 하나씩 정합니다.

코드를 보고 판단한 결과, 처음 제안된 방식(CSS 변수 + `<html data-theme>`)이 맞습니다. 이유: 화면이 모두 인라인 스타일이라 `style={{ background: 'var(--panel)' }}` 로 글자만 바꾸면 되고, React 상태 · 다시 그리기 없이 속성 하나로 온 화면이 바뀌며, 새 라이브러리가 필요 없습니다.

① **색 이름표는 `index.html` 의 `<style>` 에 둡니다**(새 CSS 파일을 만들지 않음 — 지금도 기본 스타일이 거기 있음). `:root` = 어두운 화면(3.1 의 값 그대로), `:root[data-theme="light"]` = 고르신 시안의 값.

```
--bg #0f1117 · --bg-col #11141c · --bg-deep #0c0f16
--panel #13161f · --panel-2 #161a26 · --panel-head #1a1f2e · --chip #1e2433
--border #232838 · --border-2 #2a3142
--text-strong #f1f5f9 · --text #e2e8f0 · --text-soft #cbd5e1 · --text-2 #94a3b8 · --text-3 #64748b · --text-4 #475569
--accent #3b82f6 · --accent-text #60a5fa     --ok #10b981 · --ok-text #34d399
--warn #f59e0b · --warn-text #fbbf24         --danger #ef4444 · --danger-text #f87171
--violet #8b5cf6 · --violet-text #a78bfa     --cyan #06b6d4 · --cyan-text #67e8f9
--on-fill #fff (색 단추 위 글자 — 두 주제에서 같음)   --scrim rgba(0,0,0,0.6)   --scheme dark
```

② **처음 그릴 때 깜빡이지 않게**, `index.html` `<head>` 에 몇 줄짜리 스크립트로 `localStorage` 의 값을 읽어 `<html data-theme>` 을 React 보다 먼저 붙입니다. nginx 에 CSP 머리말이 없어 인라인 스크립트가 막히지 않습니다(`frontend/nginx.conf` 확인).

③ **투명도를 이어 붙이는 곳**(`c + '18'`, `ri.color + '15'` — TopBar 1, Registration 3, Consultation 2, Lab 2, Payment 1, Settings 4줄)은 `var(--…)` 뒤에 글자를 붙일 수 없습니다. `color-mix()` 는 **쓰지 않습니다** — Chrome 111 이상이 필요한데 현장의 오래된 PC(Windows 7·8 은 Chrome 109 가 끝)에서 색이 통째로 사라집니다. 대신 **옅은 색 이름표를 미리 정의**합니다: `--accent-a12`, `--accent-a18`, `--accent-a20`, `--accent-a40`, `--ok-a18`, `--ok-a40`, `--warn-a20`, `--danger-a18` … (어두운 화면 값은 지금의 여덟 자리 색 그대로). 이어 붙이던 코드는 작은 도우미 `tint(이름, '18')` → `'var(--' + 이름 + '-a18)'` 로 바꿉니다. 도우미는 새 파일 `frontend/src/theme.js`(디자인 세션 파일로 새로 만듦).

④ **브라우저가 그리는 것**(날짜 달력, 스크롤 막대): `Registration.jsx` 의 날짜 칸에 `colorScheme:'dark'` 가 박혀 있음 → `var(--scheme)`. 그 밖에는 지금 어두운 화면에서도 스크롤 막대가 흰색입니다(전역 `color-scheme` 없음). 어두운 화면을 바꾸지 않기 위해 전역으로는 넣지 않습니다.

⑤ **마우스를 올렸을 때**: `index.html` 의 `button:hover { filter: brightness(1.12) }` 는 밝은 화면에서 단추를 더 하얗게 만들어 안 보이게 합니다 → `--hover-filter`(어두운 화면 `brightness(1.12)` 그대로, 밝은 화면 `brightness(0.95)`).

⑥ **바꾸는 단추와 기억** (실장님 결정: 상단바 언어 단추 옆 · 계정마다 · 기본은 어두운 화면)
- 단추는 `TopBar.jsx` 의 EN·KO·FR 옆. 누르면 바로 `<html data-theme>` 을 바꾸고(기다리지 않음), 그 PC 의 `localStorage('medconnect_theme')` 에 적고, 뒤에서 서버에 저장합니다. 서버 저장이 실패해도(연결 끊김) 화면은 바뀐 채로 있고 오류 창을 띄우지 않습니다 — 색 때문에 진료가 멈추면 안 됨.
- **계정마다**: `staff` 표에 칸 `theme`(`'dark'` | `'light'`, 기본 `'dark'`). 지금 있는 계정은 모두 어두운 화면으로 시작합니다(= 기본은 어두운 화면).
- 로그인한 뒤 상단바가 뜰 때 서버의 값을 읽어 그 계정의 화면으로 맞춥니다. 같은 PC 에 다른 사람이 로그인하면 그 사람의 화면으로 바뀝니다.
- **로그인 화면**(`Login.jsx`)은 아직 누구인지 모르므로 그 PC 에서 마지막에 쓴 화면을 따릅니다(처음이면 어두운 화면). `localStorage` 값은 이 용도와 첫 화면 깜빡임 방지(②)에만 씁니다.
- 서버 쪽(안): 새 파일 `backend/src/routes/theme.routes.js`(디자인 세션 것) — `GET /api/theme` → `{ theme }`, `PUT /api/theme` `{ theme }`. 로그인만 되어 있으면 누구나, **자기 계정 것만**. 모듈 권한은 보지 않습니다. `backend/src/index.js`(공용)에 한 줄. 변경 기록(`audit_log`)에는 남기지 않습니다(진료 자료가 아님 · 기록이 시끄러워짐). 다른 길: 설정 세션이 `/auth/login` · `/auth/me` 응답에 `theme` 을 넣음 — 요청이 하나 줄지만 지금 작업 중인 설정 세션의 파일을 고쳐야 해서 추천하지 않음.
- 번역 키 `ds_themeLight` · `ds_themeDark` · `ds_themeSwitch`(ko · en · fr). 단추에는 해 · 달 기호와 함께 글자도 둡니다(기호만으로 뜻을 전하지 않음).

⑦ **그대로 두는 것**: `documents/*`, `Receipt.jsx`, `DocumentModal.jsx` 안의 종이 미리보기(종이 부분만 — 창 틀은 주제를 따름), 인쇄 창(`documents/shared.jsx` 의 `window.open` — 따로 열리는 문서라 `data-theme` 이 닿지 않음), PACS 영상 창(Orthanc — 다른 프로그램).

⑧ **SVG · canvas 로 그리는 곳은 화면 파일에 없습니다**(grep 확인 — 통계 막대도 div). `fill="var(--x)"` 가 안 먹는 문제는 생기지 않습니다.

### 3.3.1 이름표만으로 안 되는 것 — 공용 규칙과 쓰임이 정해진 이름표 (2026-09-30)

`frontend/index.html` 의 `<style id="bethesda-theme-rules">`(이름표 블록 바로 아래, 손으로 씀). 2026-09-30 의 결정(7.1 ⑦ · ⑧) 뒤로 **두 화면 모두**에 걸려 있습니다.

| 규칙 | 하는 일 | 왜 |
|---|---|---|
| `::placeholder` | 빈 칸의 예시 글자를 `--placeholder` 로, `opacity: 1` | 예시 글자는 브라우저 기본 회색(`#757575`)이라 어떤 이름표도 닿지 않았음. 흰 칸 위 4.6, 잠긴 칸 위 4.1 → `#5b6779` 로 5.7 · 5.1 |
| `input:focus-visible` (`textarea` · `select` 도) | 글자를 넣고 있는 칸에 2px 파랑 테두리(`--focus-ring`). **눌러서 들어가도, Tab 으로 들어가도 보임**(입력 칸은 `:focus-visible` 이 늘 걸림 — 실장님 결정 「눌렀을 때」) | 화면마다 입력 칸에 `outline:'none'` 을 인라인으로 넣어, 어느 칸에 글자가 들어가는지 표시가 없었음. 인라인을 이기려고 `!important` |

| `button:focus-visible` | 단추에 2px 파랑 테두리 | **키보드로 옮겨 갔을 때만.** 단추는 마우스로 누른 뒤에는 `:focus-visible` 이 걸리지 않아, 누를 때 번쩍이지 않음 |

쓰임이 정해진 이름표(화면 파일이 이렇게 써야 함):

| 이름표 | 어두운 화면 | 밝은 화면 | 어디에 |
|---|---|---|---|
| `--toast-bg` · `--toast-text` · `--toast-line` · `--toast-shadow` | `#161a26` · `#6ee7b7` · `#10b98150` · 없음 | `#ecfdf5` · `#065f46` · `#047857` · 그림자 | 화면 위에 잠깐 뜨는 「저장됨」 알림. 밝은 화면에서 바탕에 묻히지 않게 옅은 초록 카드 + 짙은 테두리 + 그림자 |
| `--fade-85` | `0.85` | `1` | 「취소됨 · 바뀜」을 흐리게 해서 나타내는 카드의 `opacity`. 흐리게 하면 그 안의 작은 글자도 같이 흐려져 흰 바탕에서 기준 밑으로 떨어지므로, 밝은 화면에서는 흐리게 하지 않음(빨간 테두리와 꼬리표가 이미 말해 줌) |
| `--viewer-text` | `#8290a3` | `#8290a3` | 영상 창의 검은 판 위 안내 글자. 두 화면에서 같음 |
| `--placeholder` · `--focus-ring` | `#8290a3` · `#60a5fa` | `#5b6779` · `#1d4ed8` | 위 규칙 |

`--fade-85` 는 2026-09-30 부터 **쓰는 곳이 없습니다** — 수납 세션이 그 카드의 투명도를 아예 뺐습니다. 이름표는 남겨 둡니다(꼭 흐리게 해야 하는 곳이 생기면 씀).

**입력 칸의 고리는 칸에서 2px 띄웁니다**(처음에는 1px). 검사실의 「낮음」 칸은 테두리가 파랑(`--accent-text`)인데 어두운 화면의 고리 색과 같아, 붙어 있으면 「테두리가 두꺼워진 것」으로만 보였습니다(임상병리 세션). 띄우면 고리로 읽힙니다. 밝은 화면도 같은 값.

**투명도로 흐리게 하지 말 것**: `opacity` 는 글자 · 테두리 · 바탕을 한꺼번에 흐리게 해서, 색을 아무리 맞춰도 대비가 떨어집니다. 「취소됨」은 `--text-3` + 줄 긋기 + 꼬리표로, 잠긴 칸은 `--field-locked` · `--text-locked` 로 나타냅니다. 꼭 흐리게 해야 하면 `--fade-85` 처럼 밝은 화면에서 1 이 되는 이름표로.

### 3.4 「어두운 화면이 전과 같다」를 증명하는 법

화면 사진을 눈으로 비교하지 않습니다. 격리 스택에서 고치기 전 · 후에 같은 화면 · 같은 자료로 **모든 요소의 계산된 색**(`getComputedStyle` 의 color · background-color · background-image · 네 변의 border-color · outline-color · box-shadow · text-decoration-color · caret-color · filter · color-scheme · opacity, 입력 칸은 안내 글자색도)을 순서대로 뽑아 글자로 비교합니다. `var(--x)` 는 계산된 값에서 실제 색으로 풀리므로, 두 목록이 한 글자도 다르지 않으면 어두운 화면은 같습니다. 도구: `wiki/reference/design/compare-in-browser.js`.

### 3.6 화면별 진행 (3단계)

한 화면을 바꾸는 순서: ① `git merge --ff-only develop` ② `node wiki/reference/design/retoken.mjs <파일>` — 색이 놓인 자리(스타일 속성 · 입력 칸인지 · 색 단추 위인지)를 보고 이름표를 고름 ③ `fields.mjs <파일>` 로 입력 칸을 칸 전용 이름표로, 그다음 도구가 남긴 것과 색을 이어 붙이는 곳을 손으로 ④ `check-dark.mjs develop <파일>` — 이름표를 어두운 값으로 되돌려 넣으면 옛 파일과 같아야 함(닫힌 창 · 드문 갈래까지) ⑤ 격리 스택에서 고치기 전 · 후 계산된 색 비교(3.4) ⑥ 밝은 화면으로 켜서 `audit-in-browser.js` 의 `__audit()` 가 빈 목록인지(눌리지 않는 단추는 예외), 눈으로도 봄 ⑦ 커밋 · 보고.

**바꾸는 단추는 맨 마지막에 넣습니다.** 화면이 하나씩 바뀌는 동안 단추가 있으면 직원이 눌렀을 때 반은 밝고 반은 어두운 화면을 보게 됩니다.

**미리 보기 (총괄 지시, 2026-09-29)**: 단추가 들어가기 전에도 끝난 화면을 밝게 볼 수 있도록, **주소 끝에 `?theme=light` 를 붙여 열면** 그 PC 가 밝은 화면으로 바뀝니다. 예: `http://localhost:9080/?theme=light`. 되돌리려면 `?theme=dark`. 한 번 열면 그 PC 의 브라우저에 기억되고(`localStorage` 의 `medconnect_theme`), 주소에서 그 부분은 바로 지워져 새로 고침이나 즐겨찾기로 다시 적용되지 않습니다. `light` · `dark` 가 아닌 값은 무시합니다. `frontend/index.html` 의 첫 화면 스크립트가 합니다. 모르는 직원은 쓸 수 없고, 단추가 들어간 뒤에 남아 있어도 해가 없습니다. 2026-09-29 밤에 모든 화면이 끝났습니다.

**로그인할 때와 상단바 — 두 곳에서 읽음**(2026-09-30): 총괄이 `api/client.js` 의 `saveAuth` 에 「로그인 답의 `theme` 으로 바로 `setTheme()`」 을 넣어, 같은 PC 에 다른 사람이 로그인할 때 앞사람의 화면이 먼저 보이지 않습니다. 상단바의 `GET /api/theme` 은 그대로 — 다른 PC 에서 바꾼 것을 화면을 옮길 때 따라잡습니다. 둘이 겹쳐 생기는 문제를 점검해 고친 것:

| 경우 | 전에는 | 지금 |
|---|---|---|
| 화면이 열리자마자(또는 화면을 옮기자마자) 단추를 누름 — `GET` 의 답이 누른 뒤에 도착 | 답이 예전 값이라 화면이 **도로 돌아감**. 느린 연결에서 실제로 생길 수 있음 | 단추를 누른 뒤 5초 안에 도착한 `GET` 의 답은 버림(`themeChosenAt` — 화면마다 상단바가 새로 그려지므로 부품 밖에 둠) |
| 같은 계정을 같은 브라우저의 두 탭에서 씀 | 한 탭에서 바꿔도 다른 탭은 그대로 | `storage` 이벤트로 다른 탭도 따라 바뀜 |
| 저장 실패(연결 끊김) | 주석은 「그 PC 에서는 바뀐 채로 있음」이라 했으나, 다음 화면을 열 때 서버 값으로 돌아감 | 동작은 그대로, 주석을 사실대로 고침. 프랑스어 설명서의 「Si ce message apparaît」 첫 줄이 이 경우 |
| 로그인 답에 `theme` 이 없거나 모르는 값 | — | `saveAuth` 가 `light` · `dark` 일 때만 적용(확인) |
| 저장된 `medconnect_user` 안의 `theme` | 단추를 눌러도 갱신되지 않음 | 읽는 곳이 없어 문제없음(화면은 `medconnect_theme` 과 서버 값만 봄) |

**알려진 것**: `/admin/staff` 가 `SELECT s.*` 라서 직원 목록 응답의 각 줄에 `theme` 칸이 새로 생깁니다. 총괄의 조건(「`/admin/staff` 응답 모양을 바꾸지 않음」)을 지키려면 `admin.routes.js`(설정 세션 파일)에서 `password_hash` 를 지우는 자리에 `theme` 도 지워야 합니다 — 디자인 세션은 그 파일을 고치지 않았습니다.

## 7. 알려진 문제 · 제약

- **지금 어두운 화면에 대비 기준 미달이 있음**: 어두운 화면을 바꾸지 않는다는 약속 때문에 그대로 두었습니다. 고칠지 여쭐 표는 아래 **7.1**.
- **지금 어두운 화면에서 스크롤 막대가 흰색**(진료 화면 문장사전 등) — 전역 `color-scheme` 이 없어서. 같은 이유로 그대로 둠.
- **진료 화면 가운데 칸이 1366 폭에서 옆으로 밀림**(배치 문제 — 디자인 세션이 고치지 않음, 진료 세션에 부탁): 프랑스어 · 한국어 모두, 처방 줄을 넣고 칸에 글자를 친 뒤 가운데 칸(`overflow:hidden`, 폭 409px 안에 내용 546px)의 `scrollLeft` 가 135 가 되어 바이탈 칸 왼쪽과 진료 기록 왼쪽이 잘려 보임. 문장사전 줄의 「검색」 칸이 칸 밖에 놓여 거기에 초점이 가면 밀리는 것으로 보임(원인은 확인하지 못함).
- 시안의 대비 수치는 접수 · 진료 두 화면에서만 잰 것. 3단계에서는 화면마다 `__audit()` 로 실제 자리에서 다시 잼.
- **접수 화면의 「차트번호」 칸**(새 환자일 때 「자동 생성」 안내가 흐리게 — `opacity 0.6`)은 밝은 화면에서 대비 4.2. 읽기 전용 안내이고 투명도는 색이 아니라서 건드리지 않음. 접수 세션이 투명도를 0.7 로 올리면 통과.
- **수납 화면 오른쪽 합계 칸이 1366 폭 · 프랑스어에서 잘림**(금액 끝의 「Ar」 이 칸 밖으로) — 배치 문제라 디자인 세션이 고치지 않음. 수납 세션의 L9(좁은 화면)와 같은 것으로 보임.
- **화면 가운데 돋보기 그림(🔎) 같은 큰 그림 글자**는 색을 바꿀 수 없는 그림이라 검사에서 뺌.
- 시안은 색을 기계로 바꿔 입힌 것이라, 실제 구현에서는 역할별 이름표로 다시 정리하면서 몇 곳의 색이 조금 달라질 수 있습니다(수치 기준은 지킴).

### 7.2 검사실 단추를 다른 화면과 맞출지 — 실장님 결정을 기다림 (2026-09-30)

> 임상병리 세션의 의견. **어두운 화면이 달라지는 일이라 실장님이 정하십니다.** 그림(실제 화면 — 지금 / 고친 뒤 / 견주어 볼 수납 화면): https://claude.ai/artifact/AfFFFmVTCaYAGokWNpDQVG · 같은 파일 `wiki/reference/design/lab-button-2026-09-30.html`(만드는 도구 `labbutton.mjs`).

어두운 화면에서 다른 화면의 주 단추는 짙은 바탕 + 흰 글자(7.1 에서 그렇게 고침)인데, 검사실의 「CBC」 같은 검사 단추와 「저장 · 완료」 단추만 밝은 청록 + 검은 글자입니다. 읽는 데는 문제가 없습니다(7.6). 다만 화면에서 혼자 가장 밝고, 간호사는 약국과 검사실을 오갑니다.

| | 지금 | 고친 뒤 |
|---|---|---|
| 단추 | 밝은 청록 `#06b6d4` → `#0891b2` + 검은 글자 | 짙은 청록 `#0e7490` → `#155e75` + 흰 글자 |
| 단추 위 글자의 대비(기준 4.5) | 7.6 | 5.4 |
| 단추가 바탕에서 눈에 띄는 정도 | 7.4 — 혼자 가장 밝음 | 3.4 — 초록 3.3 · 파랑 3.5 와 같은 수준 |
| 검사 이름, 낮음 ▼ · 높음 ▲, 고른 환자의 청록 줄 | 그대로 | 그대로 |
| 밝은 화면 | 그대로(이미 짙은 청록 + 흰 글자) | 그대로 |

**추천: 가(맞춤).** 어느 화면에서나 「짙은 바탕에 흰 글자 = 누르는 주 단추」가 되어 화면을 오갈 때 헷갈리지 않습니다. 잃는 것은 단추 글자의 또렷함(7.6 → 5.4, 기준은 넘음). 「나(그대로)」도 읽기에는 문제가 없습니다.

**어떻게 고치나**: 7.1 에서 청록을 바꾸지 못한 까닭은 임상병리 화면이 같은 `--cyan` 을 글자와 줄에도 쓰기 때문이었습니다. 그래서 **단추용 이름표를 따로** 만들었습니다 — `--cyan-fill` · `--cyan-fill-2`. 지금 값은 `--cyan` · `--cyan-strong` 과 같아서, 화면 파일이 이것을 쓰게 바꿔도 **보이는 것은 달라지지 않습니다.** 결정이 「가」로 나면 어두운 값 셋(`--cyan-fill` `#0e7490`, `--cyan-fill-2` `#155e75`, `--on-cyan` `#ffffff`)만 바꿉니다.
