## 2부 — 1차에서 하지 않은 것

### A. 지난 날 방문 (📅) — 환자 B

지난 날 방문은 화면에서 만들 수 없으므로(지난 날짜에는 새 접수가 안 됨), **격리 DB에서만** 날짜를 하루 당깁니다.

1. 간호사: 환자 B RASOA Marie 새로 등록 → 의사 선택 → 접수(오늘).
2. 준비(격리 DB만): `UPDATE visit SET visit_date = CURRENT_DATE - 1 WHERE patient_id = (SELECT id FROM patient WHERE last_name = 'RASOA');` — 결과에 「준비 SQL」로 적음.
3. 접수 설명서 «Date de travail»: ◀ → 어제 → 대기 줄에 B → **Terminer →** → 확인 창 → 「Sans frais」로 끝남. 오늘 화면으로 돌아오기(« Aujourd'hui »).
4. 수납 설명서 §10: En attente에 **📅 (어제 날짜) · visite d'un jour passé · pas encore encaissée** 줄이 있는지 → Consultation이 **Sans frais**(0 Ar)인지 → 확인 → 영수증 날짜가 **오늘**인지.
5. 한 번 더(진료 경로): 환자 B의 두 번째 방문을 같은 방법으로 어제로 당긴 뒤, 의사가 **🔍 Trouver patient → Sélection visite(어제)** 로 열어 기록·약 1줄 → Terminé → 수납 📅 줄에 진료비(Nouvelle 또는 Suivi)와 약이 있는지 → 부분 수납 없이 전액 → 영수증 오늘 날짜.
6. 통계: **Aujourd'hui**의 Caisse에 이 돈이 들어가고, **어제** 방문 수에는 B가 세어지는지(Terminer → Sans frais는 「Sans frais / autres」).
7. 약국: B의 어제 처방이 **🔍 Trouver patient**의 주황 상자(7일 안)에 나오는지 → 조제.

### B. 서류 한 장 — 환자 A

1. 진료 설명서 §10: 의사, 환자 A → **Documents** → Langue **FR** → 진단서(목록에서 가장 흔한 것 — 예: Certificat médical) → Saisie 채우기 → `[ ]`가 남으면 «⚠ À compléter»가 나오는지 → 다 채우고 **Émettre** → 번호 `D26-…` → **🖨 Réimprimer**(인쇄 창만).
2. 수납 설명서 §2.5: 이 서류가 수납에서 돈을 받는 것이면 **Délivrance / Autres → + Ajouter**(Medical Certificate) → 수납 → 영수증에 줄이 있는지. 금액이 어디서 오는지(설정의 코드) 적기.
3. 잘못 낸 경우(§10.8): Historique → **Annuler** → 사유 → «ANNULÉ». 수납에 이미 받은 서류비가 있으면 어떻게 되는지(자동 정정인지, 손으로 정정인지) 적기.
4. Journal(설정): 서류 발행·취소가 남는지(남아야 하는지는 설명서 기준 — 없으면 「남지 않음」으로만).

### C. 영상 검사 한 건 — 내기 → 취소 (환자 A)

격리 스택에는 PACS·브리지가 없습니다. 장비가 받는 목록은 API로 봅니다: `GET /api/worklist/dicom-mwl`(관리자 토큰) — 오늘 `scheduled`인 영상 검사.

1. 진료 설명서 §7 / PACS 설명서: 의사가 `Chest` 입력 → 목록에 `CR`·**WL** → Entrée → 줄 오른쪽 상태(PACS 없는 곳에서는 **Envoyé**가 안 될 수 있음 — 무엇이 뜨는지 그대로 적기).
2. API로 장비 목록에 이 환자(26-00001)가 **나오는지**.
3. 이미지가 없으므로 ✕ → «Retirer « … » ?» → 줄이 사라짐. 15초 뒤 API 목록에서 **빠지는지**(PACS 설명서 §7.3 「15초」).
4. 수납: 이 검사를 이미 받았으면 정정(환불)으로, 아니면 목록에 없음. 둘 중 하나를 골라 해 보기(1부 ⑥ 뒤에 하면 정정 경로).
5. 이미지가 있는 경우(「marquer comme annulé」, 「⊘ Images d'une demande annulée」)는 PACS가 없어 **못 함** — 결과에 그렇게 적음.

### D. 한국어 화면 한 바퀴 (짧게) — 환자 C

상단 **KO**. 접수(새 환자 C, 성별 없이 → 한국어 안내, 같은 이름 경고 창 한국어) → 진료(바이탈·약 1줄·검사 1줄 → 완료) → 검사실(결과 1개) → 약국(조제, 확인 창) → 수납(전액, 영수증) → 통계(오늘 카드) → 설정 → 기록(Journal).
각 화면에서 **프랑스어·영어가 섞여 나오는 글자**만 모읍니다(시드 데이터는 따로 표시). 금액은 쉼표(«17,300»).

### E. 밝은 화면 한 바퀴 — ☀ Clair

1. 계정마다 상단 **☀ Clair**. 새로 고침 뒤에도, 다른 계정으로 바꾼 뒤 돌아와도 **그 계정에 기억**되는지.
2. 같은 PC에서 계정을 바꿀 때 **어두운 화면이 한 번 번쩍이는지**(디자인 부탁: 로그인 응답에 `theme`).
3. 접수·진료·검사실·약국(재고 탭 포함)·수납(정정·취소·미수 창 포함)·통계·설정(기록 탭)에서 각각 `__audit()`(부모 투명도 곱한 판) — **꺼진 단추와 장식 이모지는 빼고** 4.5(큰 글자 3) 미만만 표로.
4. 인쇄물(영수증·서류)은 밝은/어두운과 상관없이 흰 종이인지.
5. **저장 알림이 보이는지**: 설정(약 저장 «✓ Enregistré», 약속처방), 검사실(저장 뒤 한 줄), 진료(Sauver), 접수(환자 저장) — 임상병리가 「밝은 바탕에 묻힌다」고 함. 알림마다 `__audit()`에 잡히는지 + 눈으로.
6. 접수 「N° dossier」 칸(잠긴 칸 이름표, 2026-09-30): 번호 글자 밝은 5.46 · 어두운 5.87(통과). 안내 글자는 디자인의 `::placeholder` 규칙이 들어온 뒤 4.5 이상인지 다시.

### F. 진료 B2 — 「대기열 서랍이 남는 것」 재현 순서

1차의 조건 그대로: 의사 계정, 프랑스어, 어두운 화면, 1366×768, 대기 1명.

1. **Consultation** → **☰ File d'Attente (1)** 클릭.
2. 서랍이 열린 뒤(0.5초) 환자 이름 클릭.
3. **바로** 화면을 봄 → 0.3초·1초·2초 뒤 다시.
4. 같은 순간 DOM으로: `getComputedStyle(document.querySelector('[data-motion="drawer"]')).transform` — 닫히면 `translateX(-290px)`(행렬 `…, -290, 0`).

2026-09-30 접수가 격리 스택에서 해 본 것: **0.3초 안에 닫힘**(0초 −0.4 px → 0.1초 −274 px → 0.3초 −290 px). 1차에서 「남아 있다」고 본 것은 **브라우저 창 캡처가 늦게 찍힌 것**으로 보임(같은 시험에서 입력칸이 비어 보인 것과 같은 현상). 다시 시험에서 눈으로(사람 화면) 한 번 보고, 남아 있지 않으면 B9를 「재현 안 됨 — 시험 도구 캡처 지연」으로 닫습니다.
