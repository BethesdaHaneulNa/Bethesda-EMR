# 환불 시뮬레이션 — 돈을 돌려줘야 할 때 EMR에서 일어나는 일 (현금 기준)

> 실장님 요청(2026-09-29): 「영수 취소 아니면 환불할 금액이 나왔을 때 어떻게 할 건지 시뮬레이션을 돌려 봐」.
> 수납 세션이 격리 스택(9183, 수납 `f9ea726` = M6 (다) 들어간 판)에서 **화면과 같은 요청을 실제로 보내** 확인했습니다.
> 스크립트: `sim.mjs`(수납 세션 작업 폴더). 실행 중 EMR에는 아무것도 하지 않았습니다.

## 먼저 요약

- **과청구가 나오면 기본은 「정정(Correction)」입니다.** 정정 화면이 **돌려줄 돈**을 계산해 주고, 그만큼만 현금으로 돌려주면 됩니다. 덜 받았던 환자는 돌려줄 돈 없이 **미수만 줄어듭니다.** 영수증 전체 취소는 환자를 잘못 고른 경우처럼 드문 일입니다.
- 영수증을 전체 취소할 때는 이제 EMR이 **「돈을 돌려줬습니까?」** 를 묻습니다(M6 (다)). 답에 따라 다시 수납할 때 받은 금액 칸이 비거나(돌려줌) 채워집니다(안 돌려줌).
- **환자·창구 사이의 돈은 네 경우 모두 맞습니다.** 미수와 돌려줄 돈도 맞습니다.
- **어긋나는 곳은 통계의 「날짜」입니다.**
  - 정정하거나 취소하면, 처음 수납한 날(D1)의 수납액이 나중에 **0으로 바뀌고**, 그 돈이 처리한 날(D2)로 옮겨 갑니다.
  - 그래서 날마다 창구 현금과 통계가 맞지 않습니다. 예: ①에서 D2의 실제 현금은 **−3,000**인데 통계는 **+15,000**입니다.
  - 기간 전체(D1+D2)의 합계는 맞습니다.
  - 그리고 **그날 돌려준 돈(환불액)** 이 통계 어디에도 나오지 않습니다.
- 고칠 선택지는 맨 아래에 있습니다. 추천은 (가) 「통계를 현금 기준으로」 — 수납과 통계 세션이 같이 하는 일입니다.

## 조건

- 진료 한 건 = 진료비(Consultation) **15,000** + 약 **3,000**(2개 × 1,500) = **18,000 Ar**.
- 경우마다 **D1 = 처음 수납한 날**, **D2 = 정정·취소한 날**로 다른 이틀을 썼습니다(9월 19일~28일). 그래서 날짜별 통계가 섞이지 않습니다.
- **통계 수납액** = 통계 화면 「Encaissé」(`/api/stats/summary`의 `revenue.paid`) — 그날 날짜의 취소 안 된 영수의 순수납 합.
- 화면 글자는 **프랑스어 / 한국어** 순입니다.
- 현금의 **+** 는 환자가 창구에 낸 돈, **−** 는 창구가 환자에게 돌려준 돈입니다.

## ① 전액 받음 → 약 하나 삭제(과청구) → 정정

| 날 | 일어난 일 · 직원이 보는 화면 | 직원 손의 현금 | 통계 수납액 D1 / D2 |
|---|---|---|---|
| D1 | 18,000 수납 (영수 R-…-9001). 환자가 18,000을 냄 | **+18,000** | 18,000 / 0 |
| D2 | 진료실이 약 3,000을 지움 → 수납 대기 목록에 **「Correction」 — 「À rembourser: 3,000 Ar」** / 「정정」 — 「돌려줄 돈: 3,000 Ar」 | 0 | 18,000 / 0 |
| D2 | 환자를 누르면 정정 화면: **Montant correct 15,000 · Total 15,000 · Déjà encaissé 18,000 → Remboursement dû 3,000** / 정확한 금액 15,000 · 총 수납액 15,000 · 이미 받은 금액 18,000 → 환불 예정 3,000 | | |
| D2 | **「Appliquer la correction」** / 「정정 처리」 → 확인 창 **「Appliquer la correction ? Le reçu actuel est annulé et réémis au montant correct. — Rendez 3,000 Ar au patient.」** / 「정정 처리하시겠습니까? … — 환자에게 3,000 Ar를 돌려주세요.」 → 새 영수증 R-…-9002 (「Remplace le(s) reçu(s) : R-…-9001」, 「Remboursé au patient : 3 000 Ar」) | **−3,000** | **0** / **15,000** |

- 끝: 환자 미수 0, 돌려줄 돈 0, 대기 목록에서 빠짐.
- **현금 합계 15,000 = 통계 합계 15,000.** 하지만 날짜별로는 D1 +18,000 / D2 −3,000이 실제인데, 통계는 D1 0 / D2 +15,000입니다.

## ② 일부만 받음 → 항목 삭제 → 미수만 줄어듦

| 날 | 일어난 일 · 화면 | 현금 | 통계 D1 / D2 |
|---|---|---|---|
| D1 | 18,000 중 10,000만 받음(미수 8,000) | **+10,000** | 10,000 / 0 |
| D2 | 약 3,000 삭제 → 목록 **「Correction」 — 「Reste impayé: 5,000 Ar」** / 「정정」 — 「남을 미수: 5,000 Ar」 | 0 | 10,000 / 0 |
| D2 | 정정 화면: **Total 15,000 · Déjà encaissé 10,000 → Impayé 5,000** / 총 수납액 15,000 · 이미 받은 금액 10,000 → 미수금 5,000. 확인 창 **「5,000 Ar resteront impayés.」** / 「5,000 Ar가 미수로 남습니다.」 → 새 영수증(부분 수납) | **0** — 돌려줄 돈 없음 | **0** / **10,000** |

- 끝: 환자 미수 **5,000**(8,000에서 줄어듦).
- 현금 합계 10,000 = 통계 합계 10,000. 날짜별로는 D1이 10,000에서 0이 되고 D2가 +10,000이 됩니다(실제 D2 현금은 0).

## ③ 전액 받음 → 영수증 전체 취소 → 다시 수납

취소 창(M6 (다)):
- 노란 안내 **「Si seuls des articles ont changé, n’annulez pas : utilisez la correction — seule la différence est rendue.」** / 「항목만 바뀌었으면 취소하지 말고 정정을 쓰세요 — 차액만 돌려줍니다.」
- 질문 **「Avez-vous rendu au patient les 18,000 Ar encaissés sur ce reçu ?」** / 「이 영수증으로 받은 18,000 Ar를 환자에게 돌려줬습니까?」

### ③a 돌려줌 — 「Oui — 18,000 Ar rendus」 / 「예 — 18,000 Ar 돌려줌」

| 날 | 일어난 일 · 화면 | 현금 | 통계 D1 / D2 |
|---|---|---|---|
| D1 | 18,000 수납 | **+18,000** | 18,000 / 0 |
| D2 | 영수증 취소, **Oui** → 영수증에 「ANNULÉ … Remboursé au patient : 18 000 Ar」, 영수내역 「Rendu à l’annulation: 18,000 Ar」 | **−18,000** | **0** / 0 |
| D2 | 목록 **「Re-facturer」** / 「정정 재수납」 → 받은 금액 칸 **비어 있음** → 환자에게 다시 18,000 받음 | **+18,000** | 0 / **18,000** |

- 현금 합계 18,000 = 통계 합계 18,000.
- D2의 실제 현금은 −18,000 + 18,000 = **0**인데 통계는 18,000입니다. D2에 돌려준 18,000은 통계 어디에도 나오지 않습니다(취소 건수 1만 보임).

### ③b 돌려주지 않음 — 「Non — l’argent reste à la caisse」 / 「아니요 — 돈은 창구에 있음」

| 날 | 일어난 일 · 화면 | 현금 | 통계 D1 / D2 |
|---|---|---|---|
| D1 | 18,000 수납 | **+18,000** | 18,000 / 0 |
| D2 | 영수증 취소, **Non** → 영수내역 「Gardé à l’annulation: 18,000 Ar」 | 0 | **0** / 0 |
| D2 | 목록 **「Re-facturer」** → 받은 금액 칸에 **18,000이 미리 들어가 있음**(「↺ Re-facturer — Paiement reporté 18,000」 / 「이월 수납액」) → 그대로 확정 | **0** — 새로 받은 돈 없음 | 0 / **18,000** |

- 현금 합계 18,000 = 통계 합계 18,000. D2에 들어온 돈은 없는데 통계는 18,000입니다.

## ④ 미수 수납 영수가 있는 내원의 정정

| 날 | 일어난 일 · 화면 | 현금 | 통계 D1 / D2 |
|---|---|---|---|
| D1 | 18,000 중 10,000 받음(미수 8,000) | **+10,000** | 10,000 / 0 |
| D2 | 영수내역 **「Encaisser impayé」** / 「미수 수납」 8,000 → 오늘 날짜의 미수 수납 영수증 | **+8,000** | 10,000 / 8,000 |
| D2 | 진료실이 약 3,000 삭제 → 목록 「Correction — À rembourser: 3,000 Ar」 | | |
| D2 | 정정 화면: **Total 15,000 · Déjà encaissé 18,000**(두 영수증에서 받은 돈 모두) **→ À rembourser 3,000** → 「Rendez 3,000 Ar au patient.」 → 새 영수증 1장이 두 영수증(처음 수납 + 미수 수납)을 대신함 | **−3,000** | **0** / **15,000** |

- 끝: 환자 미수 0.
- 현금 합계 15,000 = 통계 합계 15,000. D2 실제 현금은 +8,000 − 3,000 = **+5,000**인데 통계는 15,000입니다.

## 한눈에 — 날짜별 실제 현금과 지금 통계

| 경우 | D1 실제 현금 | D1 통계 (처리 후) | D2 실제 현금 | D2 통계 | 기간 합계 (현금 = 통계) |
|---|---|---|---|---|---|
| ① 정정, 3,000 돌려줌 | +18,000 | **0** | −3,000 | **+15,000** | 15,000 = 15,000 |
| ② 정정, 미수만 줄어듦 | +10,000 | **0** | 0 | **+10,000** | 10,000 = 10,000 |
| ③a 취소(돌려줌) → 재수납 | +18,000 | **0** | 0 (−18,000 +18,000) | **+18,000** | 18,000 = 18,000 |
| ③b 취소(안 돌려줌) → 재수납 | +18,000 | **0** | 0 | **+18,000** | 18,000 = 18,000 |
| ④ 미수 수납 뒤 정정 | +10,000 | **0** | +5,000 (+8,000 −3,000) | **+15,000** | 15,000 = 15,000 |

같은 날 안에서 처리하면(D1 = D2) 그날 통계와 현금은 맞습니다. 날짜가 넘어갈 때만 어긋납니다.

## 지금 EMR에서 어긋나는 곳

1. **이미 지나간 날의 수납액이 나중에 바뀝니다.**
   - 통계는 「취소된 영수는 없던 일」로 셉니다. 정정도 옛 영수증을 취소하고 새로 끊는 방식입니다.
   - 그래서 D2에 정정하면 D1의 수납액이 0이 됩니다. 이미 마감한 날의 장부가 바뀌는 셈입니다.
2. **처리한 날에는 「새로 받은 돈」이 아니라 「영수증 금액 전체」가 잡힙니다.** ①의 D2는 실제로 3,000을 내줬는데 통계는 +15,000입니다.
3. **그날 돌려준 돈(환불액)이 통계에 없습니다.**
   - EMR은 이제 기록은 합니다: 취소 때 돌려준 돈 `refunded_amount`(M6), 정정으로 돌려준 돈은 새 영수증의 거스름(`change_amount`).
   - 통계 화면이 이것을 읽지 않습니다.
4. **(고침)** 정정 확인 창 첫 줄이 돌려줄 돈이 없을 때도 「Traiter le remboursement ?」(환불 처리?)였습니다. 이번에 「Appliquer la correction ? …」 / 「정정 처리하시겠습니까? …」로 바꿨습니다.

## 고칠 선택지 (결정 필요 — 수납·통계 세션이 같이)

| 선택지 | 무엇이 바뀌나 | 좋은 점 | 걱정 |
|---|---|---|---|
| **(가) 통계를 현금 기준으로 (추천)** | 수납이 영수증마다 **「이미 창구에 있던 돈」** 을 기록(새 칸, 마이그레이션 3xx): 정정 영수증은 그전에 받은 돈 전부, 「돈을 안 돌려준」 취소 뒤 재수납은 칸에 미리 채워진 돈, 그 밖은 0. 통계의 「그날 받은 돈」 = 그날 영수증들(**취소된 것도 포함**)의 순수납 − 이미 있던 돈 − 그날 돌려준 돈 | 위 표의 「실제 현금」과 날마다 똑같아짐(①~④ 모두 계산으로 확인). 지나간 날 숫자가 바뀌지 않음. 환불액이 그날 음수로 보임 | 수납(칸 하나·기록) + 통계(수납액 계산 바꿈). 「매출(청구한 금액)」과 「현금」이 다른 숫자가 되므로 통계 화면에 둘을 나눠 적어야 함 |
| (나) 지금대로 + 「그날 돌려준 돈」 줄만 | 통계에 환불액 한 줄(`refunded_amount` + 정정 영수의 거스름, 날짜별) | 작음. 그날 내준 돈은 보임 | 1·2번(지나간 날이 바뀜, 처리한 날에 전액이 잡힘)은 그대로 |
| (다) 지금대로 | 직원·실장님께 「기간 합계는 맞고, 날짜별로는 처리한 날로 옮겨 간다」고 안내 | 변경 없음 | 하루 현금 마감과 통계가 정정·취소가 있던 날마다 다름 |

**수납 세션 추천: (가).** 창구는 현금이라, 하루 마감(그날 들어온 돈 − 나간 돈)과 통계가 같아야 현장에서 믿고 쓸 수 있습니다. (가)의 날짜별 숫자를 시뮬레이션 데이터로 미리 계산하면 위 표의 「실제 현금」 칸과 모두 같습니다.
