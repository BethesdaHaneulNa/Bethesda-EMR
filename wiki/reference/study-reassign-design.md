# 설계 메모 — 잘못 고른 오더로 찍힌 영상을 맞는 오더로 바로잡기

> 2026-10-01 · PACS 세션 → 총괄. **아직 짓지 않았습니다.** 총괄이 읽고, 실장님 결정이 필요한 것(8절)이 정해진 뒤에 짓습니다.
> 이 메모의 「실험」은 모두 격리 스택(EMR 9188 · PACS 9198, Orthanc 1.12.11 = 실행 중 PACS와 같은 이미지)에서 장비 흉내의 진짜 C-STORE로 한 것입니다. 실행 중 EMR·PACS는 건드리지 않았습니다.

## 0. 무슨 일인가

의사가 **Upper Abdomen US**와 **Carotid US**를 함께 냈는데, 방사선사가 장비의 목록에서 **Carotid** 줄을 고른 채 **배**를 찍었습니다. 영상은 「Carotid US」의 검사 번호·이름을 달고 영상 서버에 들어가고, EMR에서도 Carotid 오더에 붙습니다. 환자는 맞으므로 환자 번호 경고는 뜨지 않습니다 — **EMR도 영상 서버도 스스로는 알아챌 수 없는 실수**입니다(device-watch도 마찬가지).

**원칙 (실장님, 2026-10-01)**: 「올쎈에 있는 데이터가 가장 근본적인 데이터」 — **영상 서버의 자료 자체를 맞게 고친다.** 다른 병원에 영상을 내보낼 때 영상 안의 검사 번호·이름이 맞아야 하기 때문입니다. EMR의 연결은 그 결과를 따라갑니다.

**선 (라이선스)**: Orthanc **프로그램**은 고치지 않습니다. Orthanc가 공식으로 주는 기능(REST의 `POST /studies/{id}/modify`, `DELETE /studies/{id}`)으로 **자료**를 고치는 것은 Orthanc를 「쓰는」 것입니다. README License 절의 「uses Orthanc as-is (unmodified)」와 어긋나지 않습니다 — 짓게 되면 그 절에 한 문장을 더합니다: *"The clinic's own images may be corrected through Orthanc's REST API; that is using Orthanc, not changing it."*

## 1. 실험으로 확인한 것 (추측 아님)

| # | 한 것 | 결과 |
|---|---|---|
| E1 | 잘못 붙은 검사(Carotid 번호, 영상 3장)에 `POST /studies/{id}/modify` — `Replace: {StudyInstanceUID, AccessionNumber, StudyDescription}`를 맞는 오더(Abdomen)의 것으로, `Force: true`, `KeepSource: true`, `Synchronous: true` | **새 검사가 하나 더 생김**(맞는 번호·이름, 3장). **원본은 그대로 남음**. 0.02초. **그림(픽셀)은 한 바이트도 안 바뀜**(3장 모두 해시 같음). 전송 문법 그대로 |
| E1 | 바뀐 태그 | 영상 한 장의 태그 25개 가운데 **다섯만** 달라짐: 넣으라고 한 셋 + **SeriesInstanceUID · SOPInstanceUID가 새 번호**(Orthanc 기본 동작). 나머지 20개는 글자까지 같음 |
| E2 | 같은 것에 `Keep: ["SeriesInstanceUID","SOPInstanceUID"]` | 시리즈·영상 번호가 **그대로 유지**됨(`Force`가 있어야 함). 원본과 새 검사가 같은 영상 번호로 나란히 있을 수 있음 |
| E3 | **이미 있는 검사 번호로** modify(같은 환자) | 오류 없이 **그 검사에 섞여 들어감**(3장 → 5장). ⚠ 맞바꾸기를 「A를 B 번호로」부터 하면 두 검사가 섞임 |
| E4 | 원본을 `DELETE` | 지워짐. **Orthanc의 변경 기록(`/changes`)에 삭제는 남지 않음**(새로 생긴 것만 남음) → 영상 백업은 삭제를 스스로 알 수 없음 |
| E4 | 새 검사가 생긴 뒤 브리지 | 다음 주기에 **스스로 찾아 EMR에 「도착」을 알림**(`study arrived for 261001-51 (3 instances, patient match, found by uid)`) — 맞는 오더가 아직 대기 중일 때 |
| E5 | 새 영상의 Orthanc 메타 | `Origin: RestApi`, `ModifiedFrom: <원본 영상>`, **`RemoteAET`(보낸 장비 이름) 없음** → device-watch가 「어느 장비가 보냈는지」를 이 영상에서는 못 읽음 |

코드로 확인한 것:
- **영상 백업**(`image-backup.ps1`)은 영상을 `images/<StudyInstanceUID>/<SOPInstanceUID>.dcm`로 디스크에 복사하고 **지우지 않습니다**. 그래서 바로잡은 뒤에도 **옛 번호의 파일이 디스크에 남고**, 디스크로 복원하면(`restore-image-backup.ps1`은 디스크의 `.dcm`을 모두 올림) **잘못 붙은 검사가 되살아납니다.** → 4절.
- **워크리스트 feed**는 `scheduled_date = 오늘 AND status = 'scheduled'`인 줄만 장비 목록에 올립니다 → 영상을 떼어 낸 원래 오더를 다시 찍게 하려면 상태와 **날짜**를 함께 되돌려야 합니다.
- 워크리스트 파일(`.wl`)이 장비에 주는 것: 환자, `AccessionNumber`, `StudyInstanceUID`, `RequestedProcedureDescription`, `RequestedProcedureID`(= accession), `ScheduledProcedureStepSequence`(Modality, 날짜, `…StepDescription`, `…StepID`). 장비가 이 가운데 무엇을 영상에 베끼는지는 장비마다 다릅니다(진짜 장비로 **확인 필요**).

## 2. 무엇을 고치나

같은 환자의 오더끼리만 옮깁니다. **환자 태그는 건드리지 않습니다.**

| 태그 | 어떻게 |
|---|---|
| `StudyInstanceUID` (0020,000D) | 맞는 오더의 워크리스트 번호로 |
| `AccessionNumber` (0008,0050) | 맞는 오더의 것으로 |
| `StudyDescription` (0008,1030) | **지금 값이 잘못 고른 오더의 이름과 같을 때만** 맞는 오더 이름으로(장비가 목록에서 베낀 경우). 장비가 자기 프로토콜 이름을 적은 것이면 둠 |
| `RequestedProcedureDescription` (0032,1060), `RequestedProcedureID` (0040,1001), `RequestAttributesSequence` (0040,0275)의 `ScheduledProcedureStepDescription`·`ScheduledProcedureStepID`·`RequestedProcedureID` | 영상에 **있을 때만**, 잘못 고른 오더의 값이면 맞는 오더의 값으로 |
| `SeriesInstanceUID` · `SOPInstanceUID` | **그대로 둠**(`Keep`) — 3절 |
| `SeriesDescription`, `BodyPartExamined`, `ProtocolName`, 영상 자체 | **안 건드림** — 장비가 실제로 찍은 것을 적은 값 |
| 환자 이름·번호·생일·성별 | **안 건드림** |

**시리즈·영상 번호(Series/SOP UID)를 그대로 두자는 까닭**: 같은 영상이고 「어느 검사에 속하는지」만 바로잡는 것입니다. 번호를 새로 만들면 ① 그 검사 안의 보고서·측정 자료(SR)가 가리키는 영상 번호가 어긋날 수 있고(Orthanc가 함께 고쳐 주는지는 **확인 필요**) ② 같은 영상이 번호만 다른 두 벌로 백업 디스크에 쌓입니다. 그대로 두면 백업 디스크에서도 「같은 영상의 옛 자리 / 새 자리」로 짝이 맞습니다. (총괄 판단 사항 — 반대로 「고친 영상은 새 번호」가 맞다고 보시면 기본 동작으로 둡니다. 짓는 양은 같습니다.)

## 3. 두 경우의 순서 — 어느 순간에도 영상이 사라지지 않게

**규칙**: 원본은 **새 검사를 확인한 뒤에만** 지운다. 확인 = 영상 장수가 같고, 새 영상마다 `ModifiedFrom`이 원본 영상을 가리키고, 번호·accession이 넣은 값이고, 파일 크기가 원본과 거의 같음(±2%). (작은 검사는 그림 해시까지 견줌 — 장수 상한을 두고.)

### (a) 옮기기 — 맞는 오더에 영상이 없을 때

| 단계 | 하는 일 | 여기서 실패하면 |
|---|---|---|
| 0 | EMR에 「바로잡기」 한 줄을 `started`로 적음(누가·어느 오더에서 어느 오더로·사유·원본 검사·영상 번호 목록) | 아무것도 안 바뀜 |
| 1 | Orthanc `modify` (`KeepSource: true`) → 새 검사 | 원본 그대로. 새 검사가 반쯤 생겼으면 지움 |
| 2 | 새 검사 확인 | 어긋나면 새 검사를 지우고 끝(원본 그대로) |
| 3 | EMR 한 트랜잭션: **맞는 오더** ← 도착 기록(원본의 도착 시각·장수·환자 대조), 상태 「완료」 / **원래 오더** ← 도착 기록을 비움(상태는 아직 `completed` — 장비 목록에 안 올림) / 판독 처리(8절 Q2) / 변경 기록 한 줄 | EMR이 되돌려지면(ROLLBACK) 새 검사를 지움 — 원본 그대로 |
| 4 | Orthanc에서 **원본 삭제** | EMR은 이미 맞음. 원본이 남아 있는 동안은 「정리 대기」로 적어 두고 다시 시도(서버가 5분마다, 그리고 시작할 때). 원래 오더가 아직 `completed`라 브리지가 원본을 다시 붙이지 않음 |
| 5 | 원래 오더를 `scheduled` + 날짜를 오늘로 → **장비 목록에 다시 올라감**(그 검사는 아직 안 찍었으므로). 「바로잡기」 줄을 `done`으로 | 다시 시도(4와 같음) |

### (b) 맞바꾸기 — 두 오더에 영상이 서로 바뀌어 붙었을 때

E3 때문에 **임시 번호**를 거칩니다(A = 오더 1에 붙은 검사, B = 오더 2에 붙은 검사):

1. A → 임시 번호 T (A 보관) · 확인 → A 삭제
2. B → 오더 1의 번호 (B 보관) · 확인 → B 삭제
3. T → 오더 2의 번호 (T 보관) · 확인 → T 삭제
4. EMR 한 트랜잭션: 두 오더의 도착 기록(장수·시각·환자 대조)을 맞바꿈, 판독 처리, 변경 기록

각 단계에서 「새 것 확인 → 옛 것 삭제」이므로 **두 검사의 그림은 어느 순간에도 확인된 검사 하나 이상에 들어 있습니다.** 중간에 끊기면 「바로잡기」 줄의 단계 번호를 보고 **앞으로 이어서** 끝냅니다(되돌리지 않음 — 서버가 시작할 때와 5분마다). 그동안 두 오더는 `completed`라 브리지가 손대지 않고, 영상 창은 그 검사에 「바로잡는 중입니다」 안내를 보입니다.

### (c) 한 검사 안에 두 검사의 영상이 섞인 경우 — **이번 범위 밖**

같은 줄을 고른 채 배와 목을 이어 찍은 경우입니다. 일부 시리즈만 옮겨야 하는데(Orthanc는 시리즈 단위 modify도 됨 — E3의 「섞여 들어감」이 이때는 쓸모가 됨), 「어느 시리즈가 어느 검사인지」를 사람이 영상을 보며 골라야 해서 화면이 따로 필요합니다. 다음 과제로 적어 둡니다.

### 미리 막는 것 (옮기기 전 검사)

- 두 오더가 같은 환자, 둘 다 영상 오더, 둘 다 취소 아님.
- **같은 종류(modality)끼리만**(US ↔ US). CR 오더에 US 영상을 붙이는 것은 실수일 가능성이 큼 — 8절 Q5.
- 원본 검사가 **안정된 뒤에만**(Orthanc `IsStable` — 장비가 아직 보내는 중이면 「1분 뒤에 다시」).
- 원본의 환자 대조가 `match`일 때만(환자 번호 경고가 있는 영상은 「누구 것인지」부터 풀어야 함).
- 맞는 오더의 번호로 된 검사가 영상 서버에 **이미 있으면** (a)는 거절(섞임 방지) → (b)로.
- 같은 오더에 진행 중인 바로잡기가 있으면 거절(두 번 누름·두 사람이 동시에).

## 4. 브리지 · 영상 백업 · 복원

**브리지**: 고칠 것 없음. (a)에서 새 검사는 맞는 오더의 번호를 달고 있어 브리지가 스스로 찾지만(E4), EMR이 3단계에서 이미 적어 두므로 중복해서 적히지 않습니다(도착 시각은 먼저 적힌 것을 지킴). 원래 오더는 5단계 뒤 다시 장비 목록에 올라갑니다.

**영상 백업 — 고쳐야 함 (PACS 저장소)**: 지금대로면 옛 번호의 파일이 디스크에 남아 **복원할 때 잘못 붙은 검사가 되살아납니다**(그리고 (b)에서는 두 검사의 영상이 한 폴더에 섞임).
- EMR이 「바로잡으며 없어진 영상」 목록을 줍니다(브리지 토큰으로 읽는 새 길 — 검사 번호 + 영상 번호).
- `image-backup.ps1`이 밤마다 그 목록의 파일을 `images/…`에서 **`replaced/<날짜>/…`로 옮깁니다**(지우지 않음 — 원본의 마지막 보관처).
- `restore-image-backup.ps1`은 `replaced/`를 올리지 않습니다. 옛 디스크(옮기기 전 상태)로 복원한 경우를 위해, 올린 뒤 EMR의 목록에 있는 옛 검사가 영상 서버에 있으면 알려 주고 지웁니다(EMR 복원이 먼저 — 지금 순서 그대로).
- 새 검사의 영상은 평소처럼 새 번호 폴더에 복사됩니다(영상 번호를 그대로 두면 파일 이름이 같아 짝을 알 수 있음).

**device-watch**: 바로잡은 영상에는 보낸 장비 이름이 없습니다(E5). 그런 영상을 「알 수 없는 장비」가 아니라 **「EMR에서 바로잡은 영상」**이라고 말하게 한 줄 고칩니다.

## 5. EMR 쪽

- **연결**: `worklist_log`의 도착 기록(장수·도착 시각·환자 대조·`image_study_uid`)이 3단계에서 옮겨집니다. 도착 시각은 **원래 영상이 온 시각**을 지킵니다.
- **원래 오더**: 영상이 없어지고 다시 「Envoyé / 대기」로 — 장비 목록에 다시 올라감(8절 Q3).
- **판독 글**: 8절 Q2. 어느 쪽이든 두 오더의 상세에 한 줄이 남습니다: *「2026-10-01 RABE Hery가 영상을 Carotid US(09-30)에서 이 검사로 옮김 — 사유: …」*.
- **수납**: 돈은 안 바뀝니다(오더는 낸 그대로). 원래 오더는 여전히 청구 대상(검사를 다시 찍을 것이므로). 안 찍기로 하면 지금 있는 「오더 취소」로.
- **이미 발행된 판독 보고서**(다른 병원에 나간 종이): 서류 이력에 그대로 남습니다. 옮기려는 검사에 발행된 보고서가 있으면 확인 창에 「이 검사의 판독 보고서가 N번 발행되었습니다」를 보입니다(8절 Q6).
- **변경 기록**: 새 종류 `pacs.study_move` 한 줄 — 누가 · 언제 · 환자 · 「영상 3장: Carotid US(260930-52) → Upper Abdomen US(260930-51)」 · 사유. 맞바꾸기는 「↔」. (`utils/audit.js`의 종류 목록은 공용 파일 — 총괄.)
- **권한**: 8절 Q1.
- **새 표** `pacs_study_move`(마이그레이션 8xx): 종류(옮김/맞바꿈), 두 오더, 옛·새 검사 번호, 영상 번호 목록, 사유, 누가·언제, **단계와 상태**(`started` · `emr-done` · `done` · `rolled-back` · `cleanup-pending`), 오류 글. 이 표가 ① 중간에 끊긴 일을 이어 가는 근거 ② 백업이 「없어진 영상」을 아는 근거 ③ 화면의 「옮긴 기록」입니다.
- **서버 길**(PACS 세션 파일 `pacs.routes.js` 또는 새 `pacs.move.js`): `GET …/move-targets?order_item_id=`(옮길 수 있는 오더 목록과 못 하는 이유), `POST …/move`(옮기기·맞바꾸기), `GET …/superseded-images`(백업용, 브리지 토큰). Orthanc에는 EMR이 이미 가진 로그인(`pacs_config.orthanc_password` — 영상 창 중계가 쓰는 것)으로 들어갑니다.

## 6. 실패 · 중간 상태 (요약)

| 일어난 일 | 결과 |
|---|---|
| Orthanc가 꺼져 있음 / 응답 없음(1단계 전) | 「영상 서버가 응답하지 않습니다」 — 아무것도 안 바뀜 |
| modify 도중 Orthanc가 죽음 | 원본은 그대로(`KeepSource`). 반쯤 생긴 새 검사는 다음 시도 때 지우고 다시 |
| 새 검사가 확인에서 어긋남 | 새 검사 삭제, 원본 그대로, 「바로잡지 못했습니다 — 영상은 그대로입니다」 |
| modify는 됐는데 EMR 기록이 실패 | 새 검사 삭제(되돌림). 그것도 실패하면 `cleanup-pending` — 원본·EMR은 처음 그대로, 서버가 남은 새 검사를 나중에 지움 |
| EMR은 됐는데 원본 삭제가 실패 | EMR은 맞음. 원래 오더는 아직 장비 목록에 안 올림. 서버가 다시 시도, 화면에 「정리 대기」 |
| 맞바꾸기 도중 끊김 | 단계 번호를 보고 앞으로 이어 감. 그동안 두 검사의 영상 창에 「바로잡는 중」 |
| 서버 PC 전원이 나감 | 다시 켜지면 `started`·`cleanup-pending` 줄을 찾아 이어 감 |

어느 줄에서도 **그림이 영상 서버에서 사라지는 순간은 없습니다**(원본 삭제는 늘 확인 뒤).

## 7. 화면

- **영상/판독 창의 오른쪽 상세**에 단추 **「⇄ 영상을 다른 오더로 옮기기」**(fr «Corriger la demande…») — 영상이 있고 취소가 아닌 검사에서, 권한이 있는 사람에게만.
- 누르면 작은 창:
  1. 지금 검사: 「Carotid US · 2026-09-30 · 영상 3장」과 작은 그림 대신 **「🖼 영상보기」**(옮기기 전에 정말 무엇이 찍혔는지 보게).
  2. **같은 환자의 영상 오더 목록**(같은 종류): 영상 없는 오더 → **「이 오더로 옮기기」**, 영상 있는 오더 → **「이 오더와 맞바꾸기」**. 못 고르는 줄은 흐리게 + 이유(취소됨 · 종류가 다름 · 환자 번호 경고 · 아직 전송 중).
  3. **사유**(필수, 한 줄).
  4. 확인 글: 「영상 서버의 영상 3장이 **Upper Abdomen US**의 검사로 바뀝니다. 영상 안의 검사 번호와 이름이 고쳐집니다. Carotid US는 다시 촬영 대기로 돌아갑니다. 이 일은 변경 기록에 남습니다.」 + **「옮기기」** 단추(누르는 동안 「바로잡는 중…」).
- 잘못 옮겼으면 **다시 옮기면 됩니다**(같은 기능으로 거꾸로) — 「되돌릴 수 없다」가 아니라 「되돌리려면 한 번 더 옮긴다」.
- 끝난 뒤 두 오더의 상세에 옮긴 기록 한 줄(5절).
- **설명서**: 프랑스어 «Les images sont sur la mauvaise demande» 절 — 언제 쓰는지(장비에서 다른 줄을 골라 찍었을 때), 누가, 하는 법, 한 검사 안에 두 검사가 섞였을 때는 관리자에게. 현장 순서서에도 한 줄.
