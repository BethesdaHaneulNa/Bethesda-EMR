# 시놀로지 NAS에서 EMR 돌리기 — 시험 기록

> 총괄 작성 · 2026-09-29 · GitHub 이슈 `BethesdaHaneulNa/Bethesda-EMR` 1번(2026-06-30, 열림)의 뒤따름 확인

## 한 줄 요약

**지금 묶음(`docker-compose.yml`)은 시놀로지에서 그대로는 돌아가지 않습니다.** DSM 방화벽이 켜져 있으면 같은 네트워크의 컨테이너끼리 통신이 막혀, EMR 프로그램(api)이 DB에 닿지 못합니다. 6월에 본 것과 같습니다. 컨테이너가 NAS의 네트워크를 직접 쓰는 방식(`network_mode: host`)으로는 연결됩니다.

## 한 것과 결과 (2026-09-29)

시험용 컨테이너만 만들고 끝에 모두 지웠습니다(네트워크 `emrtest`, 컨테이너 `emrtest-db`·`emrtest-hostdb`). 기존 프로그램, 방화벽 규칙, 시스템 설정은 건드리지 않았습니다.

| | 시험 | 결과 |
|---|---|---|
| A | 같은 네트워크에 DB(`postgres:16-alpine`)와 클라이언트를 띄워 이름 찾기 · ping · 5432 연결 | 이름은 찾음(172.22.0.2). **ping 3개 중 0개 받음, 5432 응답 없음** — 이슈의 문제 ② 그대로 |
| B | 둘 다 `--network host`, DB는 `127.0.0.1:55432`만 열고 연결 | **연결됨** |
| C | 컨테이너 안에서 인터넷 주소 찾기(`registry.npmjs.org`) | **시간 초과** — 이슈의 문제 ① 그대로 (빌드 중 시험은 출력이 없어 판정하지 못함) |

NAS에서 이미 돌고 있는 병원 프로그램 가운데 서로 통신해야 하는 것(보고관리·IP 콘솔·챗봇·Updater)은 모두 host 방식입니다. 컨테이너 하나짜리는 브리지로도 문제가 없습니다.

## 시놀로지로 가려면 해야 할 일

정해진 것은 「현지의 새 PC에 설치」(`decisions.md`)입니다. 아래는 시놀로지로 바꿀 때의 일 목록이고, 아직 아무것도 만들지 않았습니다.

1. **EMR용 시놀로지 설정 파일** — db·api·web을 host 방식으로. DB는 `127.0.0.1`에서만 듣게, 웹(nginx)이 api를 `127.0.0.1`로 찾게. NAS에서 이미 쓰는 포트와 겹치지 않는지 확인(지금 병원 NAS: 3080·3090·3091·3099·9000·9010).
2. **PACS도 같은 처리** — Orthanc와 워크리스트 브리지. 장비가 보내는 4242는 방화벽에서 장비 주소만 허용.
3. **빌드는 NAS에서 하지 않음** — 인터넷 없는 설치 묶음(미리 만든 이미지)을 `docker load`로. 문제 ①을 피해 감. NAS에서 해 본 적은 없음.
4. **영상 백업** — 지금 스크립트는 Windows용(PowerShell)뿐. NAS에서는 `.sh`를 새로 만들거나 DSM의 Hyper Backup을 씀.
5. **운영 도구** — `server-status`·`verify-backup`·`pair-with-emr`의 `.sh`는 Git Bash에서만 확인됨. NAS(busybox)에서 돌려 봐야 함.
6. **가져갈 기기에서 다시 시험** — 위 결과는 병원 NAS의 것. 다른 기기·다른 DSM이면 다를 수 있음.

## 하지 않기로 한 길

- DSM 방화벽 끄기, `bridge-nf-call-iptables=0`으로 바꾸기: 시스템 설정을 바꾸는 일이고 재부팅하면 되돌아갑니다. 이슈에 후보로 적혀 있으나 시험하지 않았습니다.
